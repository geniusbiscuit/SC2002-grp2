# Test notes

## How to run

```
mvn test                                                     # unit tests (needs internet the first time for JUnit)
scripts/replay.sh scripts/stage2-victory.txt                 # Stage 2 runs
scripts/replay.sh scripts/stage2-defeat.txt
scripts/replay.sh scripts/stage1-victory.txt --regular-only  # Stage 1 runs
scripts/replay.sh scripts/stage1-defeat.txt --regular-only
```

Each line in a script is what a player would type. The game echoes it, so the output reads like a real
session. Saved transcripts are in `docs/runs/`.

## Recorded runs

| Stage | Run | Result |
|---|---|---|
| 1 | Victory | 5 paid, $66.00, average satisfaction 79.2 |
| 1 | Defeat | Only "Wait": 0 paid, $0.00, 2 customers left |
| 2 | Victory | 5 paid, $73.50 (VIP pays $13.50 for a Burger), average 75.6 |
| 2 | Defeat | Only "Wait": 0 paid, 2 left (the Regular and the Critic) |

The Stage 1 transcripts are byte-for-byte the same when replayed on the Stage 2 code with `--regular-only`,
so Stage 1 behaviour did not change.

The victory scripts were generated by `GreedyManager` (in `src/test/.../support`): the Waiter serves if
possible, otherwise takes an order, otherwise seats the least satisfied customer, and the Chef works on the
order closest to done.

## Unit tests

| Test class | What it checks |
|---|---|
| `TurnRulesTest` | The brief's worked example turn by turn, staff order, one action per staff per turn, serving only on a later turn, rejected choices, abandonment, win targets, 18 turns, max five payments |
| `EntityRulesTest` | Food rule, Cashier order and timing, table freed after payment, satisfaction never below 0 |
| `ScriptedRunTest` | Stage 1 and 2 scripts through the real UI, bad input asked again |
| `CustomerBehaviourTest` | Waiting loss 8/5/12, VIP discount, Critic's dish, every customer type reaching payment, no type checks in the controller |
| `MoneyTest` | Cents formatting and rounding |
